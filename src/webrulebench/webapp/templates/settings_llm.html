Kullanım

  • Test: seçili modele kısa bir istek gönderir ("yalnızca OK yaz"); süre, yanıt ve token sayısını ya da hatayı gösterir. Herkes test edebilir.
  • + Yeni backend, Düzenle, Sil yalnızca admin'e açıktır. Değişiklik hemen geçerlidir; sunucuyu yeniden başlatmak gerekmez.

API tipleri

  • ollama — yerel Ollama (/api/chat); anahtar gerekmez. Model listesi makinedeki Ollama'dan canlı okunur: ollama pull ile eklenen model hemen görünür. Kayıtta yalnızca varsayılan model (★) ve formlarda gizlenenler tutulur. "▸ Modeller" parametre sayısı, quantization, bağlam uzunluğu, boyut, yetenekler ve digest'i gösterir.
  • anthropic — Anthropic Messages API.
  • gemini — Google generateContent; URL'de {model} yer tutucusu bulunur.
  • openai — OpenAI uyumlu /chat/completions: OpenAI, Groq, NVIDIA NIM, OpenRouter, DeepSeek, LM Studio, vLLM… URL taban adrestir (…/v1).

API anahtarları

Anahtar değeri llm_models.json'da değil, proje kökündeki .env dosyasında (ya da ortam değişkeninde) tutulur; ortam değişkeni önceliklidir. Sayfada yalnızca son 4 karakter görünür. Backend silinince .env'deki anahtar silinmez.

Tekrarlanabilirlik

Ollama modelleri için deney kaydına modelin digest'i (dosya özeti), parametre sayısı, quantization ve bağlam uzunluğu da yazılır: aynı etiket (ör. qwen2.5-coder:7b) yeniden çekilirse model dosyası değişebilir; digest deneyin hangi dosyayla çalıştığını sabitler. Makinede yüklü olmayan bir modelle deney başlatılamaz.

Üretim parametreleri

temperature, top_p, max_tokens (ve Ollama için seed, num_ctx) model karşılaştırmasını doğrudan etkiler. Varsayılanlar backend düzeyindedir; "▸ Modeller" tablosundaki Ayar sütunundan (✏️) tek bir model için üzerine yazılabilir — ör. düşünen (thinking) modellerde daha yüksek max_tokens. Her deney kullanılan birleşik değerleri ve modele özel olanları backend_snapshot olarak kaydeder. max_tokens çok alanlı şablonlarda (özellikle uzun regex'lerde) yanıtın kesilmemesi için yeterli olmalıdır.

Usage

  • Test: sends a short request to the selected model ("reply with OK only"); shows the time, reply and token count, or the error. Anyone can run tests.
  • + New backend, Edit and Delete are admin only. Changes take effect immediately; there is no need to restart the server.

API types

  • ollama — local Ollama (/api/chat); no key needed. The model list is read live from Ollama on the machine: a model added with ollama pull appears immediately. Only the default model (★) and the models hidden in forms are stored. "▸ Models" shows the parameter count, quantization, context length, size, capabilities and digest.
  • anthropic — Anthropic Messages API.
  • gemini — Google generateContent; the URL contains the {model} placeholder.
  • openai — OpenAI-compatible /chat/completions: OpenAI, Groq, NVIDIA NIM, OpenRouter, DeepSeek, LM Studio, vLLM… The URL is the base address (…/v1).

API keys

Key values are not stored in llm_models.json but in the .env file in the project root (or in an environment variable); the environment variable takes precedence. Only the last 4 characters are shown on the page. Deleting a backend does not delete its key from .env.

Reproducibility

For Ollama models the model's digest (file hash), parameter count, quantization and context length are also written to the experiment record: if the same tag (e.g. qwen2.5-coder:7b) is pulled again the model file may change; the digest pins the file the experiment ran with. An experiment cannot be started with a model that is not installed on the machine.

Generation parameters

temperature, top_p, max_tokens (and seed, num_ctx for Ollama) directly affect model comparisons. Defaults are set per backend; they can be overridden for a single model in the Settings column (✏️) of the "▸ Models" table — e.g. a higher max_tokens for thinking models. Each experiment saves the combined values used and the model-specific ones as backend_snapshot. max_tokens must be high enough that the response is not truncated for templates with many fields (especially long regexes).
