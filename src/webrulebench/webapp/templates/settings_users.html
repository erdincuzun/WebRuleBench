İşlemler

  • + Yeni kullanıcı: güçlü bir token otomatik üretilir ve bir kez gösterilir.
  • Token yenile: yeni token üretir; eski token ve onunla açılmış bütün oturumlar (diğer cihazlar dahil) hemen kapanır. Kendi token'ınızı yenilerseniz bu oturum açık kalır ve tarayıcıda kayıtlı token güncellenir.
  • Rol: annotatör ↔ admin. Son admin'in rolü düşürülemez.
  • Pasifleştir: kullanıcı giriş yapamaz ve açık oturumları kapanır; annotation'ları, κ hesabına katkısı ve geçmişi korunur. Kullanıcı silinmez — annotation, derleme ve deney kayıtları kullanıcı adına bağlıdır. Son admin ve kendi hesabınız pasifleştirilemez.

Güvenlik

Token'lar data/users.json'da düz metin değil, tuzlu SHA-256 özeti olarak saklanır; dosya ele geçse bile token okunamaz. Hatalı giriş denemeleri yavaşlatılır ve hata mesajı kullanıcı adının var olup olmadığını söylemez. Her işlem dataset/deletion_audit.log'a yazılır.

Admin token'ını unuttum

Başka bir admin varsa sizin token'ınızı bu sayfadan yeniler. Tek admin sizseniz sunucu makinesinde:

webrulebench users reset-token <kullanıcı>
webrulebench users create-admin <kullanıcı>   # ilk kurulum / yeni admin
webrulebench users list

Web üzerinden kurtarma bilerek yoktur: sunucu dosyalarına erişebilen kişi zaten users.json'u değiştirebilir.

Actions

  • + New user: a strong token is generated automatically and shown once.
  • Reset token: generates a new token; the old token and all sessions opened with it (including other devices) are closed immediately. If you reset your own token, this session stays open and the token saved in the browser is updated.
  • Role: annotator ↔ admin. The last admin cannot be demoted.
  • Deactivate: the user cannot log in and their open sessions are closed; their annotations, their contribution to κ and their history are kept. Users are not deleted — annotation, compilation and experiment records are tied to the username. The last admin and your own account cannot be deactivated.

Security

Tokens are stored in data/users.json not as plain text but as salted SHA-256 hashes; even if the file is compromised, tokens cannot be read. Failed login attempts are slowed down and the error message does not reveal whether the username exists. Every action is written to dataset/deletion_audit.log.

I forgot the admin token

If there is another admin, they can reset your token on this page. If you are the only admin, on the server machine run:

webrulebench users reset-token <user>
webrulebench users create-admin <user>   # first setup / new admin
webrulebench users list

There is deliberately no recovery over the web: anyone with access to the server files can already change users.json.
