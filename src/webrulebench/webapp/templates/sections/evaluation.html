Deney nedir?

Sabit bir yapılandırmanın (model, kural dili, prompt, temizleme stratejisi) seçilen layout'lara uygulanmasıdır. Her layout için bir örnek sayfa LLM'e gönderilir ve bir kural seti üretilir (layout başına tek LLM çağrısı). Kurallar sonra layout'un tüm GT sayfalarında LLM'siz çalıştırılır ve alan bazında GT içeriğiyle, şablondaki metrikle (ROUGE-1 F1, Jaccard, exact match) skorlanır.

Sütunlar

  • Ortalama: tüm sayfa × alan skorlarının ortalaması (GT'si olmayan alanlar hariç).
  • Genelleme: örnek sayfa dışındaki sayfaların ortalaması — kural, LLM'in görmediği sayfalarda ne kadar çalışıyor.
  • Kural: CSS / XPath / Regex; CSS→REGEXN LLM'in CSS ürettiği ve regex'e REGEXN ile çevrildiği koşuldur.

İki yol

  • ⚡ Hızlı test: bir modeli tek bir layout'ta otomatik prompt ile dener; sonuç hemen görünür, kaydedilmez (istenirse kaydedilir).
  • ⚖ Karşılaştırmalı deney: bir ya da birden çok model × kural dili, seçilen layout'larda; birden çok seçilirse bir grup oluşur (sıralama, ısı haritası, layout bazında kazanan ve modeller arası uyum — cross check).

Kullanım

  1. Deney arka planda çalışır, ilerlemesi burada görünür. Grup üyeleri tek satırda toplanır.
  2. Bir satıra tıklayınca deneyin ayrıntıları (alan, şablon ve layout bazında skorlar, üretilen kurallar) açılır.
  3. İki deneyi işaretleyip ⚖ Karşılaştır ile ortak layout'larda yan yana görün.

Kayıt

Her deney experiments/<id>.json dosyasına yazılır: yapılandırma, kullanılan prompt'ların tam metni, üretilen kurallar, sayfa × alan skorları, token ve süre. Sunucu yeniden başlarsa çalışan deney "yarıda kaldı" olur ve kaldığı yerden sürdürülebilir. Deneyi giriş yapan herkes başlatabilir; durdurma/silme sahibine ve admin'e açıktır.

Komut satırı

# Sayfayı yapısal iskelete indir
python -m webrulebench.pipeline.skeleton data/dataset/raw/<domain>/article_001.html --show

# Seçilen backend ve kural diliyle kural üret
python -m webrulebench.pipeline.llm_extractor data/dataset/raw/<domain>/article_001.html --backend ollama --rule-type css

What is an experiment?

An experiment applies a fixed configuration (model, rule language, prompt, cleaning strategy) to the selected layouts. For each layout one sample page is sent to the LLM and a rule set is generated (one LLM call per layout). The rules are then run without the LLM on all GT pages of the layout and scored field by field against the GT content with the template's metric (ROUGE-1 F1, Jaccard, exact match).

Columns

  • Mean: mean of all page × field scores (fields without GT are excluded).
  • Generalisation: mean over pages other than the sample page — how well the rule works on pages the LLM has not seen.
  • Rule: CSS / XPath / Regex; CSS→REGEXN is the condition where the LLM generates CSS that is converted to regex with REGEXN.

Two ways

  • ⚡ Quick test: tries one model on a single layout with the automatic prompt; the result is shown immediately and is not saved (it can be saved if you wish).
  • ⚖ Comparative experiment: one or more models × rule languages on the selected layouts; if several are selected a group is created (ranking, heat map, per-layout winner and agreement between models — cross check).

Usage

  1. The experiment runs in the background and its progress is shown here. Group members are collected in a single row.
  2. Click a row to open the experiment's details (scores per field, template and layout, generated rules).
  3. Tick two experiments and use ⚖ Compare to see them side by side on their common layouts.

Storage

Each experiment is written to experiments/<id>.json: configuration, full text of the prompts used, generated rules, page × field scores, tokens and duration. If the server restarts, a running experiment becomes "interrupted" and can be resumed where it stopped. Anyone who is logged in can start an experiment; stopping/deleting is open to its owner and admins.

Command line

# Reduce a page to its structural skeleton
python -m webrulebench.pipeline.skeleton data/dataset/raw/<domain>/article_001.html --show

# Generate rules with the selected backend and rule language
python -m webrulebench.pipeline.llm_extractor data/dataset/raw/<domain>/article_001.html --backend ollama --rule-type css
