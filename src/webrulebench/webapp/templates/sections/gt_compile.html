Kullanım

  1. Tabloda her satır bir alan, her sütun bir annotatördür; Mevcut GT sütunu kayıtlı GT'yi gösterir. Bir hücrenin üzerine gelince önizlemede eşleşen elemanlar vurgulanır.
  2. K1 — Selector: kural uyumu (aynı normalize kuralı yazan annotatör çiftlerinin oranı) ve en sık yazılan kural önerisi. K2 — İçerik: önizlemedeki sayfada ⚡ İçerik Karşılaştır ile ROUGE / Jaccard skorları.
  3. 💡 Otomatik Seç etkin katmanın önerilerini uygular; hücreye tıklayarak alan bazında değiştirebilirsiniz (admin).
  4. Sayfa Birleşimi: GT'de bu layout'a atanacak sayfaları seçin, sonra 💾 GT'ye Kaydet.

Kayıt

Seçilen kurallar ve sayfalar ground_truth/approved/{{ domain }}.json dosyasına yazılır; kimin ve ne zaman derlediği layout'a kaydedilir (layout listesindeki "güncelleme var" durumu buna göre hesaplanır). Bir annotatörün seçimi alınırken XPath ve Regex'i de varsa birlikte kaydedilir.

Kural dilleri

  • CSS | XPath | Regex sekmeleri her dili ayrı derler: her sekmede o dilin annotatör seçimleri, kural uyumu ve K2 skorları ayrı hesaplanır. Sekmedeki 3/10 seçili alan sayısıdır.
  • GT'ye dahil: işaretli olmayan dil GT'ye yazılmaz; daha önce GT'de varsa kaydedince çıkarılır. Hangi dillerde GT oluşturulacağına admin karar verir.
  • Kaydedilecek sütunu o dil için GT'ye yazılacak kuralı gösterir; hücre seçimiyle dolar, admin elle de yazabilir (boşaltırsanız alan o dilde GT'ye yazılmaz).
  • XPath önizlemede tarayıcının DOM'unda, Regex ham HTML üzerinde (sunucuda) çalışır; Regex eşleşmeleri sayfada vurgulanamaz.
  • Regex sekmesinde ↻, alanın CSS'inden (CSS sekmesindeki seçim, yoksa mevcut GT) regex üretir — REGEXN (Uzun, 2020) yaklaşımının genişletilmiş hali; sonuç layout'un sayfalarında CSS ile doğrulanır. Elle kural girilen dil otomatik olarak GT'ye dahil edilir.

Kayıtta dahil edilen dillerin seçimleri alan bazında birleştirilir: yalnızca CSS varsa düz metin, aksi halde {css, xpath, regex}.

↻ yalnızca destek amaçlıdır: üretilen regex bir öneridir, düzenleyip kaydetmek kullanıcıya aittir. Üretim şu makaledeki yaklaşımın genişletilmiş halidir:
Uzun, E. (2020). A regular expression generator based on CSS selectors for efficient extraction from HTML pages. Turkish Journal of Electrical Engineering & Computer Sciences, 28(6), 3389–3401. doi:10.3906/elk-2004-67

Usage

  1. In the table each row is a field and each column an annotator; the Current GT column shows the saved GT. Hovering over a cell highlights the matching elements in the preview.
  2. K1 — Selector: rule agreement (share of annotator pairs that wrote the same normalized rule) and the most frequent rule as the suggestion. K2 — Content: ROUGE / Jaccard scores on the preview page with ⚡ Compare content.
  3. 💡 Auto select applies the suggestions of the active layer; you can change them per field by clicking a cell (admin).
  4. Page union: select the pages to be assigned to this layout in the GT, then 💾 Save to GT.

Saving

The selected rules and pages are written to ground_truth/approved/{{ domain }}.json; who compiled the layout and when is stored with the layout (the "has updates" status in the layout list is computed from this). When an annotator's rule is taken, their XPath and Regex are saved with it if present.

Rule languages

  • The CSS | XPath | Regex tabs compile each language separately: in each tab the annotators' rules, rule agreement and K2 scores of that language are computed separately. The 3/10 on a tab is the number of selected fields.
  • Include in GT: a language that is not checked is not written to the GT; if it was in the GT before, it is removed on save. The admin decides which languages the GT is created for.
  • The To save column shows the rule that will be written to the GT for that language; it is filled by selecting a cell, and the admin can also type it by hand (if you clear it, the field is not written to the GT in that language).
  • In the preview, XPath runs on the browser's DOM and Regex on the raw HTML (on the server); Regex matches cannot be highlighted on the page.
  • In the Regex tab, ↻ generates a regex from the field's CSS (the selection in the CSS tab, otherwise the current GT) — an extended version of the REGEXN (Uzun, 2020) approach; the result is verified against the CSS on the layout's pages. A language in which a rule is entered by hand is automatically included in the GT.

On save, the selections of the included languages are merged per field: plain text if there is only CSS, otherwise {css, xpath, regex}.

↻ is only an aid: the generated regex is a suggestion; editing and saving it is up to the user. The generator is an extended version of the approach in this paper:
Uzun, E. (2020). A regular expression generator based on CSS selectors for efficient extraction from HTML pages. Turkish Journal of Electrical Engineering & Computer Sciences, 28(6), 3389–3401. doi:10.3906/elk-2004-67
